## Requirement Clarity

- [ ] CHK001 Is "the code email cannot be sent" defined — a send-time rejection only, or also a later bounce — so the visitor-facing failure message has a definite trigger? [Ambiguity, Spec §FR-011]
- [ ] CHK002 Is "visible to the owner" specified concretely enough to be built and verified for a failed acknowledgement or reply notice, rather than leaving the surface unstated? [Clarity, Spec §FR-047, §FR-052]
- [ ] CHK003 Does the copy-layer requirement state explicitly that email subjects and bodies count as copy, so all three messages are covered rather than only on-screen text? [Clarity, Spec §FR-041]

## Requirement Completeness

- [ ] CHK004 Are the required contents of the code email specified — at minimum that it states the validity window — rather than only what it must not contain? [Completeness, Spec §FR-008, §FR-012]
- [ ] CHK005 Are requirements defined for how this feature behaves in non-production and preview environments, where sending to a real enquirer's address would be a live-data leak? [Gap]
- [ ] CHK006 Is the timing relationship between the acknowledgement and the owner's enquiry notifications specified — that the acknowledgement must not delay, block, or be batched with the owner fan-out? [Gap, Spec §FR-044, §FR-047]
- [ ] CHK007 Is it stated as a requirement, not only as an assumption, that the visitor acknowledgement does not count toward the two-independent-channel enquiry guarantee? [Traceability, Constitution §VI, Assumptions]

## Requirement Consistency

- [ ] CHK008 Are the "no code, no session, no sign-in link" constraints stated consistently for all three visitor-bound messages, including the code email itself? [Consistency, Spec §FR-046, §FR-050, §FR-012]
- [ ] CHK009 Do the requirements consistently treat a delivery failure as visitor-visible for the code but owner-only for the acknowledgement and reply notice, with the reason for the difference recorded? [Consistency, Spec §FR-011, §FR-047, §FR-052]
- [ ] CHK010 Is the single-email-channel constraint consistent with the requirement that this feature introduce no second provider or credential set, including for the acknowledgement and reply notice? [Consistency, Spec §FR-010]

## Edge Case & Scenario Coverage

- [ ] CHK011 Is "the first time a reply is saved" defined for the case where a reply is written, cleared, and later written again — does the second write notify? [Edge Case, Gap, Spec §FR-049, §FR-051]
- [ ] CHK012 Are requirements defined for a reply saved on an enquiry that carries no submitter address, including what the admin must show instead of implying a notice was sent? [Coverage, Spec §FR-049, Edge Cases]
- [ ] CHK013 Are requirements stated for repeated delivery failure to the same address — whether anything changes after the first failure, or every attempt is treated identically? [Gap, Coverage]
